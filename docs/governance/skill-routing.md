# Agent Skill Routing — LazyPrompting

**Status:** foundation contract, not installed executable agents.

## Independent policy
Follow root `AGENTS.md` and `GITHUB_RULES.md`. Other OpenITStudios projects have distinct numbers of skills and work lanes; copying their registry literally would misroute this product. Maintain 1:1 **decision and safety discipline**, not Minecraft/Blockbench domain semantics.

## Semantic lanes (not additional agents)
- PLAN / RESEARCH: read-only architecture, evidence and compatibility investigation.
- DEVELOP: explicitly authorized source changes on selected `Local`.
- VALIDATE: test or inspect exact-source evidence with actual available capabilities.
- OPERATE: future approved runtime only after legal, security, transport and acceptance gates.

A task may select one primary lane; do not create redundant specialist lanes merely for browser, prompts, costs or logs. Cross-lane handoff is explicit and retains the original goal, proof and permissions.

## Eight-method selection
Karpathy + Ponytail are one default coding/review discipline. Pstack for targeted diagnosis; Harness² only for isolated, frozen, measurable comparisons; DeepSeek Harness for session/tool lifecycle; REA only with lawful authorized targets; UI UX Pro Max for real UI; Matt Pocock for module/domain precision. None grants a runtime, external tool or user approval.

## Required preflight
Identify exact repo/ref/HEAD, semantic owner, task lane, read/write scope, external effects, capability, proof, STOP boundary. Unknown write paths are denied. All other repos are read-only unless the user separately authorizes writes.

## Planned skills
No new `SKILL.md` is created until a bounded skill contract, unique semantic ownership, SPEC/SOURCES/EVAL, and permission evaluation are approved.
